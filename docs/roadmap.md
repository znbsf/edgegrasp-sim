## 项目目的

建设一个**可复现、可比较、能解释失败原因的视觉抓取实验平台**。
平台需要回答：机器人能否根据视觉完成任务，失败发生在哪里，以及替换算法是否带来可测量改进。
感知/抓取算法给出候选，既有时间、身份、坐标、规划和轨迹门控决定是否执行；
任务成功由独立观察器判定。Blender 用于检查已有记录，不产生新的物理验证结论。

两条主线是：机器人完整操作闭环，以及其他人在干净环境中的复现能力。
后续再扩展评测和可替换算法；实机是有条件的独立阶段。

## 阶段一：完成可重复操作循环（进行中）

2026-09-06 本地进展：携物场景已获用户确认并实现，AM 控制位置在同一仿真内连续 3/3 轮完整通过。
已修复关节/时钟快照竞争、抬升阶段同源目标选择及观察基线时序；根据实际 RGB-D 姿态，
在原控制候选 ±0.5° 内有限选择肩转位姿，保留原 1 mm 中心、阶段位置、指垫间隙和安全锁存。
AM 整轮重试 0、轮间控制器重启 0；每轮独立物理抓取和下一轮几何门均通过。
旧失败组完整保留，旧 K/L/M 未通过后来补上的姿态几何门。两个平移位置的完整循环尚未验证，阶段一继续保留进行中。
历史见[首次记录](release-cycle-result.md)，当前结果见
[迭代记录](release-cycle-iteration.md)。携物场景与接触边界的进一步修改见
[已确认提案](carried-scene-proposal.md)。当前最新候选和实际结果以迭代记录为准。

目标：识别 → 接近 → 下探 → 闭合 → 抬升/保持 → 放回 → 松开 → 撤离 → 就绪。
首先限制在已有控制位置，同一方块和现有代理模型内。

1. **释放根因**：从现有 `gripper_release.log`、门控、FJT 和控制器日志定位失败；
   区分动作未接受、执行失败、门控锁存、机械张开及 effort 控制权归还。只做证据支持的最小修复。
2. **操作闭环**：加入受规划/门控约束的放回和撤离，保留独立落放、张开与接触解除证据。
   不靠关闭观察器、放宽新鲜度、清除错误锁存或重启控制器制造成功。
3. **重复循环**：单次通过后，预先声明控制位置连续 3 次完整循环，不在循环间手工修复控制器。
   若失败则保留该次尝试并暂停定位原因；不自动不断重试到凑齐成功。
   控制位置通过后，再为两个已声明平移位置分别设计少量验证，不能直接推广结果。

验收：

- 每轮抓取仍通过独立同帧双指接触、至少 20 mm 抬升和至少 0.5 s 保持。
- 方块放回允许区域并稳定受支撑，夹爪实际张开、离开方块且撤离成功；
  落放位置、稳定时间和撤离阈值在执行前依据模型/遥测确定并写入配置，不能事后调整通过线。
- 正常终态无需控制器停用回退，下一轮从明确的就绪状态开始。
- 指令被拒、观测异常或执行失败时明确停止；所有成功、失败、回退分别记账。
- 测试、精确命令、全部尝试日志、机器可读结果与代表性回放齐全。

任务入口：[下一会话交接说明](tasks/next-release-cycle.md)。

  对大数据/网络下载写明需求，不悄悄依赖原来的私有工作区。

自动化安装不代表授权改动系统、重启或使用远端资源。

## 阶段三：建立小型评测集（未开始）

目标：对稳定性、拒绝能力和失败类型做可比较评测。

- 在运行前声明少量代表性位置、角度与遮挡条件，以及每个条件的尝试数。
- 先满足场景和无执行规划条件再运行；保留不可达/不可信输入的拒绝结果。
- 分别统计完整循环成功、感知拒绝、规划拒绝、控制失败、滑落和释放失败。
- 每次记录场景、算法/配置版本、源时间、结果、失败阶段和回放入口。
- 重复尝试、修复后复测和首次尝试分开统计；失败和超限样本不从分母中移除。

验收：一条评测入口生成逐次明细及汇总；仅对实际覆盖条件给出结果，不宣传全工作空间成功率。

## 阶段四：接入可替换算法（未开始）

目标：保留现有简单颜色/几何方案作为基线，使算法改进可以在相同条件下比较。

- 定义感知输出与抓取候选接口：身份、源时间、坐标、置信信息、姿态和失败原因。
- 算法不直接驱动关节；统一走既有安全检查、MoveIt 规划和类型化门控。
- 每次只接入一个明确方法，固定数据与评测条件，与基线比较成功/拒绝、误差及计算开销。
- 新方法的模型下载、外部服务或费用单独依据用户授权；不把大模型接入当作阶段成功。

验收：同一评测入口可切换基线与新方法，接口回归通过，差异有逐次证据支撑。

## 阶段五：条件满足后迁移实机（未开始，需独立授权）

前提：限定仿真闭环和复现流程可用，用户明确将具体硬件纳入范围。
顺序：标定与坐标/时间核对 → 保守空载动作 → 停止/释放检查 → 有界单物体试验。
实机接触、摩擦、误差和停止行为重新测量，不沿用仿真数值作为实机证据。
购买硬件、远端访问和自动抓取都不是本路线图隐含授权。

## 执行与维护原则

- 优先完成阶段一；环境准备可先做文档/脚本梳理，避免同时扩展物体、算法和硬件。
- Blender 展示按诊断需要小步改进，不把视觉包装作为下一阶段的主要目标。
- 每个阶段保留可交接的基线、任务范围、验收和未解决问题；先核对当前代码再工作。
- 本次请求是记录计划，未启动新实验。路线图和任务文件不替代当前会话授权及 AGENTS.md。
- 发布阶段成果时更新 README 和本表，提交/推送按当时用户授权执行。
