# 携物场景修正：已确认，控制位置三连已验证

用户在本任务中于 2026-09-06 明确“确认”，已授权本提案范围。
实现已完成，AM同仿真三轮通过；实际证据见[迭代记录](release-cycle-iteration.md)。此说明本身不替代会话授权，结果限当前控制位置仿真。

## 已核对的问题

`planning_scene_loader.py` 的 `expected_collision_objects()` 从静态场景契约
生成方块位置，后续读回验证要求精确符合该位置。当前未表示夹起后随末端运动的方块。
因此 E/G 放回候选的目标方块碰撞需要在正确的携物模型中重新核对；不能据此
认定它们都是误报。F 还存在夹爪本体—桌面碰撞，即使修正携物模型也不得忽略。

## 具体修改范围

1. `planning_scene_loader.py`：新增明确的“世界中 / 随夹爪携带 / 已放回”状态，
   保留同一方块 ID。附着时用新鲜 RGB-D 方块姿态与同源时间的末端 TF 求相对位姿；
   不能从仿真真值生成位置，不能只删除世界方块。
2. 状态转换期间撤销场景 ready；读回验证世界物体、附着物体、尺寸、位姿、
   允许接触表和当前代次一致后才重新 ready。失败、过期或 epoch 变化保持拒绝。
3. `complete_release_cycle.py`：独立抓取证据通过后申请附着；进入放回时单独声明
   方块—桌面的预期接触。夹爪本体—桌面、非指垫—方块碰撞仍禁止。
   张开且支撑稳定后，根据新鲜 RGB-D 解除附着并放回世界；完成读回后才撤离。
4. `probe_grasp_candidate_plan_only.py`：相同的状态转换用于无执行规划。
   记录输入来源、哈希、附着相对位姿、场景代次、所有允许接触关系和零执行计数。
   旧的五段规划不能作为新携物契约的准入证明。
5. 零运动回归覆盖来源/TF 不匹配、过期、epoch 回退、读回不一致、目标丢失或重复、
   意外扩大允许接触关系。通过后重做独立规划，再做一次完整循环；单次成功后
   才单独声明同一仿真中的连续三次预算。

## 为什么单独确认

这不再只是修改放回位姿：它改变原固定场景准入契约，并新增放回阶段的
方块—桌面允许接触关系，涉及此前要求保持的安全边界。
现有 E/F/G 候选和 Windows 测试通过均不构成这项边界变更的批准。
不需要修改 AGENTS.md 或 Skill，也不涉及远程、硬件或冻结进程试验。

确认后继续实现、零运动检查、独立规划及原预算内单次完整循环。
